# Consolidado: CI Data Hub — Repositório Central de Métricas

## Visão

Criar `CiDataHub` como ÚNICA fonte de dados para TODOS os scores, dashboards, relatórios e dados do projeto. Constrói sobre a infraestrutura existente do Sprint C (Git-as-Database).

## Contexto: Sprint C (Git-as-Database)

O Sprint C já construiu:
- `StoreBackend` interface → `GitBackend` + `FsBackend`
- `Store` domain logic (index, branch, reports, metrics)
- `session-context.ts` (resolveSessionContext, resolveTestDataSource)
- `git-artifact-downloader.ts` (download de artifacts do CI)
- `ci-detect.ts` (detecção de provider)

**Pendente do Sprint C:**
- GC-07: `metrics.ts` usando Store (Store é per-project, metrics é global — precisa análise)
- GAP-3: `GitStoreBackend.flush()` nunca chamado por `saveMetrics()` — dados escritos mas nunca commitados no git

**O CiDataHub completa o que o Sprint C started:** usa a infraestrutura de StoreBackend para persistir dados do CI, e fornece uma interface unificada para todos os consumidores.

## Fase 3 — Criar CI Data Hub

**Arquivo novo:** `shared/ci-data.ts`

```typescript
interface CiDataHub {
    runs: PipelineRun[];
    jobs: Map<number, PipelineJob[]>;
    failureReasons: Map<number, string[]>;
    artifacts: Map<number, ArtifactInfo[]>;

    passRate: number;
    avgDuration: number;
    suiteSpeedP95: number;
    topFailingJobs: Array<{ name: string; failureRate: number }>;
    branchBreakdown: Record<string, { passRate: number; count: number }>;
    flakyTests: Array<{ name: string; rate: number; runs: number }>;
    defectTrends: Array<{ date: string; failures: number; fixes: number }>;
    costEstimate: { totalMinutes: number; estimatedCost: number };
    releaseScore: number;
    quarantineStatus: Record<string, { rate: number; quarantined: boolean }>;
    coverage?: number;

    lastFetched: Date;
    provider: 'github' | 'gitlab';
    repo: string;
}
```
