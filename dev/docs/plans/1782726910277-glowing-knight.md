# Plano de Correção — Pós-Diagnóstico Fase 0

## Diagnóstico: Por que algumas ferramentas falharam

### 1. quality-check.ts — TIMEOUT
**Causa:** O check `checkEslintBaseline()` roda `eslint.lintFiles(['.'])` programaticamente, lintando TODOS os arquivos do projeto com regras type-checked (typescript-eslint) + SonarJS recommended. Isso é extremamente lento e excedeu o timeout de 120s.

**Solução:** Não alterar a ferramenta. O ESLint já roda via pre-commit (lint-staged) e CI. O quality-check.ts é um gate adicional que pode ser otimizado depois.

### 2. scan-sec-logs.sh — ERRO DE SINTAXE
**Causa:** Bug na linha 71 — expressão aritmética mal formada.

**Solução:** Corrigir a linha 71 do script.

### 3. SonarJS — MUITAS VIOLAÇÕES
**Causa:** `sonarjs.configs.recommended` está habilitado no eslint.config.mjs. Isso inclui dezenas de regras que detectam padrões como:
- `sonarjs/cognitive-complexity` — funções complexas demais
- `sonarjs/publicly-writable-directories` — diretórios publicamente graváveis
- `sonarjs/no-os-command-from-path` — comandos de OS via PATH
- `sonarjs/prefer-regexp-exec` — usar RegExp.exec() em vez de String.match()
- E muitas outras

**Solução:** As regras SonarJS são legítimas e devem ser respeitadas. Cada violação deve ser corrigida no código, não desabilitando as regras.
