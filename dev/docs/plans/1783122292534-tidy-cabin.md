# Multi-line Input + Jira Ticket Fetch — Plano de Implementação

## Problema

Todo input de texto descritivo usa `ask()` (single-line). Campos como user story, critérios de aceitação, descrição de bug e passos para reprodução ficam limitados a uma linha.

## Terminologia

Em Jira, o identificador de um issue é chamado **"ID do Jira"** (ex: `PROJ-123`), não "chave". O plano usa "ID" em todo input ao usuário para evitar confusão com token/chave de API.

## Fase 2: Novo módulo `shared/prompt-input-editor.ts`

Seguir o padrão lazy-import do projeto (cf. `prompt-input-inquirer.ts:72-89`).

### Estrutura

```ts
// Cache do módulo (mesmo padrão de _inputMod, _selectMod, _confirmMod)
let _editorMod: unknown = null;
export function __setEditorMod(mod: unknown): void { _editorMod = mod; }

async function _loadEditor(): Promise<unknown> {
    if (_editorMod !== null) return _editorMod;
    try {
        _editorMod = await import('@inquirer/editor');
        return _editorMod;
    } catch {
        _editorMod = false;
        return false;
    }
}
```

### Função `askMultiline(label, options?)`

- **TTY + módulo disponível**: `@inquirer/editor` — abre editor do sistema ($EDITOR), usuário digita livremente, salva, fecha. Texto capturado retorna como string.
- **Fallback (sem editor)**: `readline.createInterface` do Node — acumula linhas, termina com **linha vazia dupla** (Enter duas vezes) ou **Ctrl+D**.
- Suporta nav commands (`/back`, etc.) → `CancelError`
- Suporta `default` como no `ask()`

### Opção de arquivo alternativa ao invés de editor

Para usuários que preferem colar texto de um arquivo:

```ts
export async function askMultilineFromFile(label: string): Promise<string> {
    const filePath = await ask(label + ' — informe o caminho do arquivo (ou deixe vazio para digitar)');
    if (!filePath.trim()) return askMultiline(label);
    return fs.readFileSync(filePath.trim(), 'utf8');
}
```

**Decisão**: Implementar APENAS `askMultiline` por enquanto. A opção de arquivo pode ser adicionada depois sem breaking changes.

## Fase 4: Modificar `jira_management/commands/case18.ts`

### `gatherInput()` — nova lógica

```
1. showSelect('Como deseja fornecer a user story?', [
     { name: 'Buscar pelo ID do Jira', value: 'jira' },
     { name: 'Digitar manualmente', value: 'manual' }
   ])

2. Se 'jira':
   a. ask('ID do Jira (ex: PROJ-123)')
   b. Validar: /^[A-Z]+-\d+$/i
   c. c.jiraResource.getJiraResource(`issue/${id}?fields=description,summary`)
   d. Extrair description
   e. Se vazio/null → warn('Issue sem descrição') + askMultiline
   f. Se ok → mostrar preview + askConfirm('Usar esta descrição?')
   g. Se não → askMultiline

3. Se 'manual':
   askMultiline('História do usuário (user story)')

4. acceptanceCriteria:
   askMultiline('Critérios de aceitação')
```

### Imports a adicionar

```ts
import { ask, askMultiline, askConfirm, showSelect, warn, info, printError, title, divider } from '../../shared/prompt.js';
```

### Notas

- `CommandContext.jiraResource` é do tipo `JiraResource` (extends `JiraClient`) — tem `getJiraResource()` disponível
- Preview da descrição: truncar em 500 chars + `...` para não poluir o terminal
- Validação do ID: regex `^[A-Z]+-\d+$` case-insensitive
